# 作业单 CSV 导入导出 · 值班处置一页

> 面向值班同学：文件交换出问题时按本页处置。格式细节见 [work-order-csv-exchange.md](work-order-csv-exchange.md)。

## 三个入口

| 干什么 | 调哪里 |
| --- | --- |
| 拿导入模板 | `GET /api/work-orders/import-template`（仅表头，Excel 打开直接填） |
| 导出作业单 | `GET /api/work-orders/export`（可加 `?status=CREATED` 等过滤） |
| 批量导入 | `POST /api/work-orders/import`，multipart 字段名 `file` |

## 铁律（先记住这三条）

1. **导入是幂等的**：单号已存在的行只跳过、不报错、不改数据。拿不准就**重跑整个文件**，已成功的行自动跳过，不会重复建单。
2. **每行独立成败**：部分行失败不影响其他行。看返回里的 `rows`，按 `lineNo`（表头算第 1 行）回原文件定位，改完**整个文件重跑**即可，不用只挑失败行。
3. **面积不能走 CSV**：轨迹核算面积是权威口径，只能走 `/api/work-orders/{id}/track-area` 登记；CSV 里写面积列会被忽略。状态、面积由系统流程产生，导出的参考列仅供查看。

## 常见情况对照

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 整批被拒：`表头缺少必需列` | 表头被改/删，或用了旧模板 | 重新下载模板，把数据贴进模板再导；表头按**列名**识别，顺序可调但不能改名 |
| 行失败：`作业单号不能为空` | 该行单号列空白 | 补单号后重跑整个文件 |
| 行失败：`农机编码不存在` | 编码写错，或农机未建档 | 与农机台账核对编码；先建农机（`POST /api/machines`）再重跑 |
| 行失败：`农机已停用` | 农机已 DISABLED | 确认是否录错编码；确需作业的走农机变更流程，不在本接口处置 |
| 行失败：`不能以 -R 结尾` | 单号占用了红冲反向单保留后缀 | 换单号；`-R` 后缀由红冲操作自动产生 |
| 行失败：`超长（≤N字符）` | 单号≤40、类型≤40、地块≤80、备注≤255 | 精简内容后重跑 |
| 行结果 `SKIPPED` | 单号已存在（重复导入/文件内重复） | **正常**，幂等跳过，无需处置 |
| 行失败：`作业单号 X 已存在` | 两批同时导入同一文件撞单 | 重跑一次即转为 `SKIPPED`，数据不会重复 |
| 导入后 Excel 再打开乱码 | 文件被另存时丢了 BOM 或转了编码 | 不影响已导入数据；重新导出获取带 BOM 的文件，或用 Excel「数据→自文本/CSV」选 UTF-8 打开 |
| 导出文件里没有 `-R` 结尾的单 | 红冲反向单不参与文件交换（设计如此） | 查反向单走 `GET /api/work-orders?orderNo=原单号-R` |
| 导出的单导入别库后状态不对 | CSV 只交换主数据，状态/面积不交换 | 属预期；状态流转、面积登记在目标库按流程补做 |

## 文件怎么准备才不出错

- 用模板填，**另存为「CSV UTF-8（逗号分隔）」**；WPS/Excel 默认的「CSV」可能是 GBK，导入会乱码——真收到了 GBK 文件，先用 Excel 另存为 UTF-8 再导。
- 字段里有逗号、引号、换行不用手工转义：Excel 保存时会自动处理；程序生成文件时按 RFC 4180 转义（引号包围、引号双写），规则见交换规范文档。
- 空行会被忽略，不计入总数；全空的文件会被拒（`导入文件为空`）。

## 升级路径

- 单次导入失败原因看不懂、或怀疑数据错乱：保留**导入文件原件 + 返回的 batchNo**，找开发查 `t_request_record`（`biz_type = WORK_ORDER_IMPORT`，请求号 = `batchNo-行号`）与 `t_work_order` 对账。
- 重复导入后计数对不上（成功+跳过+失败 ≠ 文件数据行数）：同样留证升级，不要手工改库。
